## Prerequisites

- [Bun](https://bun.sh/) — primary package manager and runtime
- [Node.js](https://nodejs.org/) 18+ (used by some sub-tools like Playwright)
- [Obsidian](https://obsidian.md/) — for plugin testing
- [Git](https://git-scm.com/)

Optional for sharing your local dev server with others:
- [Tailscale](https://tailscale.com/) — for tailnet-only sharing
- [Cloudflare Tunnel](https://www.cloudflare.com/products/tunnel/) (via `bun x cloudflared`) — for public URL sharing

## Clone and install

```bash
git clone https://github.com/cybersader/crosswalker.git
cd crosswalker
bun install
```

That installs the plugin's dependencies. The docs site has its own separate `node_modules` in `docs/` that gets installed automatically on first use of the orchestrator.

## The local dev orchestrator — `bun run serve`

From the repo root, `bun run serve` is an **interactive menu** wrapping every local workflow. It's the recommended entry point for development — it handles cross-OS `node_modules` contamination automatically (e.g. rollup native binary mismatches when bouncing between WSL and Windows), auto-installs `docs/node_modules` on first run, and cleans up all spawned children on Ctrl+C.

```bash
bun run serve
```

```
━━━ Crosswalker local serve ━━━

  1) Docs dev server          http://localhost:14321   HMR, for KB editing
  2) Docs preview (built)     http://localhost:14321   built site
  3) Docs build only          → docs/dist
  4) Plugin dev (watch)       → test-vault
  5) Docs + plugin dev        both in parallel
  6) Share docs (Tailscale)   tailnet only
  7) Share docs (Cloudflare)  public URL
  8) Docs e2e tests           playwright test:local

  Choose [1-8]:
```

### Non-interactive shortcuts

```bash
bun run serve:docs       # Option 1 — docs dev server
bun run serve:plugin     # Option 4 — plugin watch
bun run serve:both       # Option 5 — docs + plugin in parallel
bun run serve:share      # Option 6 — docs + Tailscale
```

### Windows double-click launchers

Four `.bat` files at the repo root, for when you'd rather double-click than open a terminal:

| File | Runs | Use |
|---|---|---|
| `serve.bat` | `bun run serve` | Interactive menu (docs / plugin / both / tunnel / tests) |
| `serve-docs.bat` | `bun run serve:docs` | Docs dev server only → http://localhost:14321/crosswalker/ |
| `dev.bat` | `bun run serve:plugin` | Plugin watch build only, skipping the menu |
| `reset.bat` | `node scripts/reset-test-vault.mjs` | Clears ad-hoc test imports from `test-vault/` — previews what would be deleted, then waits for a keypress to confirm |

All four `cd` to the repo root first (so they work from anywhere) and pause on exit so the window stays open if something errors. `serve.bat` and `serve-docs.bat` run through Windows `bun` directly; `dev.bat` and `reset.bat` shell out to WSL (matching how the underlying watch build and reset script are normally run).

## Plugin development workflow

```bash
# Watch mode — rebuilds plugin on file changes, outputs to test-vault
bun run serve:plugin
# or the raw command:
bun run dev
```

Then:
1. Open `test-vault/` in Obsidian (File → Open vault → select `test-vault`)
2. Enable Crosswalker in **Settings → Community plugins**
3. Trigger the plugin via command palette: **Crosswalker: Start here: import structured data**
4. Edits to `src/` auto-rebuild. Reload the plugin in Obsidian (toggle in settings or Ctrl+R in the dev console) to pick up changes
5. Install the [Hot Reload](https://github.com/pjeby/hot-reload) community plugin in `test-vault/` for automatic plugin reloads on rebuild

## Docs site development workflow

```bash
bun run serve:docs
```

Opens the Astro dev server at `http://localhost:14321/crosswalker/`. HMR is active — edits to `.mdx` files hot-reload in the browser (with the exception of inline `<style>` blocks in MDX files, which sometimes require a full page refresh).

**Do not** open `docs/` as an Obsidian vault — content files are `.mdx`, not `.md`. Use VS Code with the [MDX extension](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx) for rich editing.

## Running both in parallel

Common when working on a feature that touches both plugin code and docs:

```bash
bun run serve:both
```

Starts the docs dev server **and** plugin watch build in the same terminal. Single `Ctrl+C` kills both cleanly.

## Build commands (raw)

These all work standalone if you prefer not to use the orchestrator:

| Command | Description |
|---------|-------------|
| **Plugin** | |
| `bun run dev` | Plugin watch mode, outputs to `test-vault` |
| `bun run build` | Plugin production build (type-check + bundle) |
| `bun run test` | Plugin Jest unit tests |
| `bun run test:watch` | Plugin unit tests in watch mode |
| `bun run lint` | ESLint with obsidian-plugin rules (required for community plugin submission) |
| `bun run lint:fix` | Auto-fix lint issues |
| `bun run e2e` | Plugin E2E tests (WebdriverIO, requires Obsidian) |
| `bun run e2e:xvfb` | Same E2E suite on a private virtual display (Xvfb). Use for screenshot specs; it keeps working when the monitors sleep |
| **Orchestrator** (interactive menu wraps the workflows below) | |
| `bun run serve` | Interactive 8-mode menu — docs dev, plugin watch, parallel both, tunnel sharing, tests, MDX check |
| `bun run serve:docs` | Shortcut: docs Astro dev server (mode 1) |
| `bun run serve:plugin` | Shortcut: plugin watch build (mode 4) |
| `bun run serve:both` | Shortcut: docs dev + plugin watch in parallel (mode 5) |
| `bun run serve:share` | Shortcut: docs dev + Tailscale tunnel (mode 6) |
| **Fixtures + spec** | |
| `bun run fixtures` | Regenerate Tier 1 test fixtures into `test-vault/Frameworks/NIST-mini/` from `tools/fixtures/synthetic/nist-mini.csv`; also re-emits the committed reference `.base` views from `tools/fixtures/examples/` (`--examples` flag) |
| `bun run reset` | Clear ad-hoc test imports from `test-vault/` (dry-run by default; `-- --yes` to delete). Removes only Crosswalker-generated notes outside the protected corpus (`_licensed/`, `NIST-mini/`, `_crosswalker/`, `GRC analysis/`, `PROVENANCE.md`). Double-click `reset.bat` for a preview-then-confirm one-click |
| **Docs** | |
| `cd docs && bun run dev` | Docs Astro dev server |
| `cd docs && bun run build` | Docs production build → `docs/dist` |
| `cd docs && bun run preview` | Serve the built dist locally |
| `cd docs && bun run test:local` | Docs Playwright E2E tests |
| `bun run check:mdx` | Lightweight MDX syntax pre-check (catches bare braces, unclosed tags, frontmatter YAML errors) — fast (~1–2s) |
| **Release** | |
| `bun run version` | Bumps version in `manifest.json` + `versions.json`; stages git changes for commit |

See the [testing page](/crosswalker/development/testing/) for details on each test surface.

## Releasing

1. `bun run version` — bumps `manifest.json` + `versions.json` to the version already set in `package.json`.
2. Add a `## [x.y.z]` heading to `CHANGELOG.md` with the notes for that version. The release workflow uses that section verbatim and fails if it is missing or empty; there is no fallback body.
3. Merge to `main`. `.github/workflows/release.yml` builds, tags, and publishes the three plugin assets.
4. `0.x` versions and any version with a suffix publish as prereleases, not as the latest release.
5. A version whose tag or release already exists is skipped with a notice. The workflow never deletes, moves, or overwrites published state, so republishing means shipping a new version.

`scripts/release-preflight.mjs` makes those decisions and is covered by `tests/release-preflight.test.ts`, so they can be checked without running Actions.

## First-time sanity check

After cloning and `bun install`, verify the setup works:

```bash
# Plugin builds cleanly
bun run build

# Plugin tests pass
bun run test

# Plugin lints cleanly
bun run lint

# Docs dev server starts
bun run serve:docs
# Open http://localhost:14321/crosswalker/ and check the homepage loads
```

If the plugin build or docs dev server fails with a rollup native-binary error (e.g. `Cannot find module @rollup/rollup-<platform>`), just re-run `bun run serve` — the orchestrator auto-detects the contamination and reinstalls `docs/node_modules` with the correct platform binaries.
