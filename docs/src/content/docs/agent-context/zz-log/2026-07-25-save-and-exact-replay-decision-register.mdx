<Aside type="caution" title="This is a decision register, not a decision">
A **decision register** is a working log of open choices — what was found, what the options are, what each one costs. Nothing in it is policy until the owner ratifies it. This register (the log tracking how a saved import can be re-run later and produce the same result) is not settled. Three read-only audits checked the proposed **Save and exact replay** slice against the [five-mechanism grammar](/crosswalker/agent-context/zz-log/2026-05-04-target-structure-synthesis/), the [artifact roles and authority model](/crosswalker/concepts/artifact-roles-and-authority/) (the concept page defining which artifact is allowed to assert what), and prior provenance/migration/audit research. The direction survives. Eight decisions do not have answers yet, and each one changes what gets built.

For an executive-readable version of all eight — plain-English title, tradeoffs, and a recommendation — see the [owner review queue](/crosswalker/agent-context/zz-log/2026-07-25-owner-review-queue/) (the single checklist of everything awaiting the project owner's ratification) § 1c. This page is the evidence; that page is the decidable surface.

## Verdict in one line

The direction is the natural next layer around Crosswalker's existing primitives, but the generic reproducible-build sketch that produced it must not be implemented verbatim.

| Question | Answer |
|---|---|
| Does it conflict with schema-as-primitive? | **No** — provided stored recipes stay canonical and schema-validated |
| Does it conflict with the closed 5-mechanism grammar? | **No** — provided the binding never gains row-dependent target behavior |
| Does it conflict with `render(Recipe, ConceptIdentity)`? | **No** — the binding sits around the pure function, not inside it |
| Does it conflict with the `RecipeDocument` preservation boundary? | **No** — it is the natural completion of it. (`RecipeDocument` is the wrapper that keeps a saved recipe byte-faithful to the original it was derived from, patching rather than rebuilding it.) |
| Does it conflict with artifact roles and authority? | **No** — provided the new objects stay subtypes, bindings, descriptors, and index state |
| Can it be implemented as originally sketched? | **No** — eight decisions below are load-bearing and unanswered |

## Illustration 2 — five digests, five different questions

The single biggest correction. The existing `computeRecipeHash()` at `src/generation/hash.ts` is **not** a recipe-artifact digest, and must not be repurposed as one.

<div class="not-content sr-fig" role="img" aria-label="Five distinct digests: recipe document digest for exact revision identity, effective target hash for output behavior drift, source byte digest for exact source identity, binding digest for the locked input set, and concept CID for pre-render concept identity.">

## The eight open decisions

### Gate 1 — before the design specification

**Sequencing:** D1 must be decided **after** the [primitives reconciliation register](/crosswalker/agent-context/zz-log/2026-07-25-primitives-reconciliation-decision-register/)'s Gate 1 (schema fields), because adding Tier 1 fields after digests are locked would invalidate stored hashes.

**Ratified 2026-09-06 — Gate 1 is closed.** The options below are preserved as the record of what was considered; the owner's answers are:

| # | Ratified answer |
|---|---|
| **D1** | (a) a separate `recipe_document_digest`; every existing hash and ancestry field keeps its current meaning and stored value; `sha256-<hex>` is the only accepted syntax |
| **D2** | (a) a closed set of explicit parser, destination, and write-policy override fields; no arbitrary or free-form parameters |
| **D3** | (a) equivalence of Crosswalker-managed content, excluding run metadata that legitimately changes and user-owned edits. Tightened: byte-identical whole files are neither promised nor implemented as an opt-in check now |
| **D4** | (c) verified reselection and optional retained copies with explicit per-binding status. Tightened: explicit opt-in is required before any retained copy of a source file is stored, unconditionally; ordinary in-memory parsing is not what this gates. Location, quota, and the mobile path remain separate open questions |

Full rationale and non-commitments: [Gate 1 ratification](/crosswalker/agent-context/zz-log/2026-09-06-save-and-exact-replay-gate-1-ratification/). This unblocks the design specification only — nothing below has been implemented, and D5–D8 remain open.

| # | Decision | Options | Connects to |
|---|---|---|---|
| **D1** | **Hash taxonomy.** Add a full canonical recipe digest (a fingerprint identifying the exact recipe revision) without disturbing the existing effective-target hash (which answers only "did output-affecting behavior change?"). Also pick one wire syntax. | (a) new `recipe_document_digest` field, leave `recipe.hash` alone; (b) rename `recipe.hash` to `effective_target_hash` with migration. Syntax: keep `sha256-<hex>` everywhere, or allow `sha256:<hex>` | [v0.1 schema spec](/crosswalker/agent-context/v0-1-schema-spec/) · [Terminology](/crosswalker/concepts/terminology/) · [Recipe fidelity](/crosswalker/agent-context/zz-log/2026-07-21-portable-import-recipe-fidelity-synthesis/) · `spec/tier1.schema.json`, `spec/recipe.schema.json`, `src/generation/hash.ts` |
| **D2** | **Binding parameter surface.** A **binding** is the record joining a saved recipe to the specific inputs it ran against: which file, which sheet, where output goes, what to do on conflict. A free-form parameter bag would create a hidden sixth mechanism. | (a) closed parser/destination/policy union only, no general parameters; (b) additive Recipe Schema change declaring typed parameter slots | [Target-structure synthesis](/crosswalker/agent-context/zz-log/2026-05-04-target-structure-synthesis/) · [Hierarchy primitives](/crosswalker/concepts/hierarchy-primitives/) · [ETL and import](/crosswalker/concepts/etl-and-import/) |
| **D3** | **What "exact replay" promises.** Byte-identical whole files are not currently achievable because `produced_at`, producer version, and `user_preserve` (the regions of a note the user owns and the tool must never overwrite) all vary. | (a) managed-projection equivalence, excluding execution-scoped provenance and user-owned regions; (b) byte-identical only into a clean destination | [Conventions](/crosswalker/concepts/conventions/) · [Consistency models](/crosswalker/concepts/consistency-models/) · `src/generation/provenance.ts`, `src/generation/frontmatter-merge.ts` |
| **D4** | **Source retention.** A hash verifies bytes; it does not recover them. | (a) retain bytes by default in a content-addressed store; (b) verified reselection only; (c) both, with explicit per-binding status. Plus: vault-visible vs plugin-private, quota, license/privacy warnings | [Ontology lifecycle · Acquire](/crosswalker/concepts/ontology-lifecycle/#acquire) · [System architecture](/crosswalker/concepts/system-architecture/) · [v0.1.7 milestone](/crosswalker/reference/roadmap/milestones/v0-1-7-exporters/) |

## Implementation gaps the audits surfaced

These are facts about the current code, not decisions. They become work once Gate 1 closes.

| Gap | Where |
|---|---|
| `sha256Hex()` takes a string; exact source hashing needs a byte-oriented path | `src/generation/hash.ts` |
| Generation call sites never pass `sourceHash`, though provenance can emit it | `src/generation/generation-engine.ts`, `src/generation/provenance.ts` |
| Draft resume reparses the current file with no digest comparison | `src/import/import-wizard.ts` |
| Drafts persist only the selected sheet; header row, JSON iterator, and filter are dropped | `src/import/draft-store.ts` |
| Destination and write policy live in workflow state, not in any durable binding | `src/import/draft-store.ts` |
| Mobile storage for retained bytes is unproven and currently scheduled at RC | [v0.1-RC milestone](/crosswalker/reference/roadmap/milestones/v0-1-rc-bundle-and-ship/) |

## What happens after Gate 1 closes

1. Write the Crosswalker-native design specification in `.workspace/`, with worked examples and acceptance cases.
2. Implement identity and binding primitives, test-first, no storage or UI.
3. Add portable storage and the retained-object store, mobile-proven.
4. Build the library and replay UI.
5. Prove full NIST CSF 2.0 and NIST SP 800-53 replay.

Small sequential waves, reviewed between each. Not one large fan-out.
