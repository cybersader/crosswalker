## 1. The incident

Milestone/roadmap pages went stale for the third time within days. Each time the cause was the same: a batch of shipped work landed, `CHANGELOG.md` `[Unreleased]` got a habit-maintained entry (per the [existing reminder](https://github.com/cybersader/crosswalker/blob/main/CLAUDE.md)), but the [v0.1.6 milestone page](/crosswalker/reference/roadmap/milestones/v0-1-6-bases-query-layer/)'s Phase 7 row, the [milestone hub](/crosswalker/reference/roadmap/milestones/) status line, [`ROADMAP.md`](https://github.com/cybersader/crosswalker/blob/main/ROADMAP.md), and [`TEST_HANDS_ON_TOUR.md`](https://github.com/cybersader/crosswalker/blob/main/TEST_HANDS_ON_TOUR.md) were only synced occasionally — restating the same delivery detail as prose that immediately started drifting again.

**Root cause**: content duplication, not missing process. The CHANGELOG reminder already existed and was being followed; the milestone/roadmap pages were *also* restating the same facts in a second, less-maintained place.

## 2. The fix — single-source rule

Milestone pages keep **only**: status (🚧/✅/📋), phase structure (the table's Phase/What-ships/Build/Manual-test columns), and acceptance criteria. **In-progress delivery detail becomes a link, not a restatement**: "see `CHANGELOG.md` `[Unreleased]` for the running delivery log" replaces multi-paragraph phase-row prose. Same rule for `ROADMAP.md`'s status section.

Applied immediately to the [v0.1.6 milestone page](/crosswalker/reference/roadmap/milestones/v0-1-6-bases-query-layer/)'s Phase 7 row — a dense paragraph covering the shape workbench, render report, variadic folders, connectedness mandate, recognized-source fast path, settings hub, and workspace tab was replaced with a two-sentence summary + a link to CHANGELOG `[Unreleased]`.

## 3. Written down where it will be obeyed

Added to the [Documentation update reminders § Path-keyed reminders](https://github.com/cybersader/crosswalker/blob/main/CLAUDE.md#path-keyed-reminders) table in the repo-root `CLAUDE.md` (the table an agent actually consults before committing):

> **Landing a batch of shipped work inside an in-progress milestone** (mid-milestone commits, not a full milestone close) → milestone-status flips edit the milestone page; delivery detail lives ONLY in `CHANGELOG.md` `[Unreleased]`; batch landings update CHANGELOG + flip status cells, nothing else.

This is a peer to the existing "Any commit... adds a CHANGELOG `[Unreleased]` entry" reminder — that row establishes CHANGELOG as canonical; this row forbids the second copy from re-forming on milestone/roadmap pages.
