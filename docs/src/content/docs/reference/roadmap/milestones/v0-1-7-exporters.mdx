## Goal

Make the portable parts of the import/export chain explicit without collapsing distinct artifact roles. [ImportRecipe](/crosswalker/concepts/terminology/#recipe) remains the reusable configuration; a separate source/run binding records the exact input and parameters selected for replay; a minimal MappingSet envelope governs portable mapping assertions; exporters serialize canonical [Tier 1](/crosswalker/concepts/terminology/) data as [STRM](/crosswalker/reference/registry/strm/)-shaped TSV, [OSCAL](/crosswalker/reference/registry/oscal/) JSON, [SSSOM](/crosswalker/reference/registry/sssom/)-flavored TSV, and CSV. See the [artifact roles and authority](/crosswalker/concepts/artifact-roles-and-authority/) and [artifact-role synthesis](/crosswalker/agent-context/zz-log/2026-07-21-artifact-roles-and-authority-synthesis/). Hybrid SSSOM↔STRM resolution remains per [v0.1 stack pivot §6](/crosswalker/agent-context/zz-log/2026-05-02-v0-1-initial-stack-pivot/).

## Scope

**In:**
- STRM-shaped TSV exporter — produces NIST IR 8278A r1 OLIR template format; Excel-friendly
- OSCAL JSON exporter — target shape must be selected explicitly before edge emission; no claim that OSCAL Profile itself contains a crosswalk mapping construct
- SSSOM-flavored TSV (optional, opt-in) — for users who want to share crosswalks with the SSSOM academic ecosystem
- CSV exporter — any generated framework folder back to a spreadsheet (scope addition, delivered 2026-07-12 ahead of plan)
- Reusable-configuration library lifecycle — canonical ImportRecipe save/open/browse/inspect/export/delete under `_crosswalker/recipes/import/`
- Separate source/run binding — recipe reference + recipe hash, exact source-byte hash, parser selectors, destination, and bound parameters; source drift is diagnosed before replay
- Nested source records and body projection — nested levels become folders, notes, sections inside the parent note, or are left out, set from the Depth dial ([decision log](/crosswalker/agent-context/zz-log/2026-09-23-body-projection-sections-inside-the-note/))
- Minimal MappingSet portability envelope — stable set identity/version, participants, membership/integrity, provenance/license, canonical SSSOM/STRM round-trip, and inspect/export UI
- Command palette entries: "Crosswalker: Export STRM TSV", "Export OSCAL JSON" (only after target shape settles), "Export SSSOM TSV"
- Roundtrip test: STRM TSV → import → STRM TSV produces identical bytes (deterministic)

**Out:**
- A generalized KnowledgeSet schema or governance model; v0.1.7 defines only the minimum MappingSet portability envelope needed for crosswalk interchange
- OSCAL catalog export (deferred to v1.0+)
- Compliance dashboards / report generation (community phase)
- AI-assisted mapping suggestions (community phase)

## Success criteria

- [ ] STRM TSV opens cleanly in Excel; column ordering matches NIST IR 8278A r1
- [ ] OSCAL target shape is explicitly selected and documented; the chosen representation validates against its published OSCAL schema. If no valid mapping-bearing target is selected, the exporter remains explicitly unsupported rather than emitting misleading JSON
- [ ] SSSOM TSV passes the `sssom-py` validator (optional CI step)
- [ ] All three exporters handle large vaults (~10K mappings) without UI freeze (cooperative yielding)
- [x] STRM and SSSOM round-trip determinism verified at both assertion and MappingSet-envelope levels (release record slice 2, 2026-10-03: `tests/mapping-set-roundtrip.test.ts` and `tests/strm-import-roundtrip.test.ts`; limitation: a typed mapping table cannot carry explicit negations or release lineage (both skipped on export, so such a set always exports as partial), 'roughly the same' (exported as 'intersects with' and comes back as that), confidence beyond tenths (rounded to the 0 to 10 strength scale), labels, per-row providers, or review columns; release identity and metadata travel in the release file beside the table)
- [x] Untouched canonical ImportRecipe retains normalized semantics, canonical JSON, identity, and deferred fields through the workbench
- [x] Customized recipe receives deterministic identity + structured ancestry without mutating the original
- [x] User can durably save, reopen, browse, inspect, export, and delete a portable reusable configuration through UI (recipe library slice 2026-10-02; reopen-then-replay proved 2026-10-03)
- [x] A saved run binding retains recipe reference/hash, exact source-byte hash, parser selectors, destination, and parameters; source drift is visible before replay (Run again slice 2026-10-02)
- [x] Full NIST CSF 2.0 and NIST SP 800-53 save/reopen/replay produce equivalent canonical Tier 1 output (replay proofs slice 2026-10-03)
- [x] A portable MappingSet retains stable identity/version, participants, membership/integrity, provenance/license, and canonical SSSOM/STRM round-trip semantics (release record slice 2, 2026-10-03; delivery detail in [CHANGELOG.md — Unreleased](https://github.com/cybersader/crosswalker/blob/main/CHANGELOG.md#unreleased--v01-implementation-in-progress-2026-05-04--present))
