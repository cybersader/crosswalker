Crosswalker is a **meta-system for [ontology lifecycle](/crosswalker/concepts/ontology-lifecycle/) management**: import an ontology into Obsidian, map it to others and to evidence, query it, and share it. This page shows current work first, then what comes after v0.1. Every significant decision is [logged with rationale](/crosswalker/agent-context/zz-log/); delivery detail lives only in [`CHANGELOG.md` `[Unreleased]`](https://github.com/cybersader/crosswalker/blob/main/CHANGELOG.md#unreleased--v01-implementation-in-progress-2026-05-04--present).

**Status last verified:** 2026-10-03 — every line re-checked against the milestone pages, CHANGELOG [Unreleased] and the 2026-10-03 decision logs

:::note[How this roadmap is maintained]
Only active and future work lives here. The [milestone hub](/crosswalker/reference/roadmap/milestones/) is the live source for v0.1.x status; if the two disagree, the hub wins. When a phase completes, its checklist moves to an archive page with a "What carried forward" section, and `ROADMAP.md` at the repo root is updated to match.
:::

## Next: v0.1.8 audit trail and v0.1-RC

- **[v0.1.8](/crosswalker/reference/roadmap/milestones/v0-1-8-audit-trail/)**: one terminal Execution Record per run, provenance and log events linked to it, git + Ed25519 + FRE 902(13) consuming it, and a separate Package Manifest per release. Nothing is built yet: no `src/audit/` exists and `spec/README.md` defines neither contract. Gate 3 of the [save-and-replay register](/crosswalker/agent-context/zz-log/2026-07-25-save-and-exact-replay-decision-register/) lands here.
- **[v0.1-RC](/crosswalker/reference/roadmap/milestones/v0-1-rc-bundle-and-ship/)**: the full chain **source bytes → recipe → mapping set → Execution Record → Package Manifest** must hold end to end, then bundle, mobile and community-submission checks. The 2026-05 bundle target of ~1.2 MB needs revisiting: the production `main.js` was 5,114,861 bytes on 2026-10-03 (source: [Tier 2 worker synthesis](/crosswalker/agent-context/zz-log/2026-10-03-tier2-worker-persistence-synthesis/) ruling W2).

## Run inside OpenClast (browser-hosted Obsidian)

Owner goal set 2026-10-03: Crosswalker runs inside OpenClast, Obsidian hosted in a browser tab, within about a month. What holds on 2026-10-03 ([synthesis §4](/crosswalker/agent-context/zz-log/2026-10-03-tier2-worker-persistence-synthesis/#4-what-the-openclast-collaboration-established)):

- Crosswalker loads unmodified: 33 commands and 2 views register, the import wizard renders, sqlite loads (source: synthesis §4)
- The [Tier 2](/crosswalker/concepts/system-architecture/) search index now persists there and on desktop (it never had, on any host), by hosting sqlite in a worker. This narrowed the 2026-05-04 [Ch 23](/crosswalker/agent-context/zz-log/2026-05-04-bundle-engine-language-synthesis/) "main thread, no Web Workers" commitment to the import engine only ([§3](/crosswalker/agent-context/zz-log/2026-10-03-tier2-worker-persistence-synthesis/#3-narrowing-the-ch-23-commitment)). Measured numbers are in `CHANGELOG.md` `[Unreleased]`
- A repeatable host check exists: `bun run e2e:openclast` ([setup](/crosswalker/development/setup/))
- Shared rule: Crosswalker runs unmodified, or removes its own native assumption; host gaps go to OpenClast as reproductions, never as Crosswalker-side shims

Open items from the same log (§5, §6):

- [ ] OpenClast's compatibility entry for Crosswalker moves from "Worker not yet exercised" to exercised once the host rerun is green
- [ ] Reopen the search index automatically if its worker crashes mid-session (today a reset or reload is needed)
- [ ] Stay within OpenClast's plugin store cap of 10 MiB unpacked; the production bundle was about 4.9 MiB on 2026-10-03 (source: ruling W2)

## Formats / Acquire: "Import anything, transform it properly" (v0.2)

XLSX and JSON parsers shipped 2026-06-12; nested JSON and framework stacks followed in 2026-09. What remains is format breadth, acquisition and transforms, keeping exact-source replay semantics.

- [ ] **JSONL parser**: not supported yet
- [ ] **Source fetch automation**: needs a per-framework rights model (fetching a restricted workbook for a user differs from pointing at it) and a pinning story so automation never silently replaces the source a recipe or replay expects
- [ ] **Remote acquisition**, kept separate from recipe transformation and layout policy
- [ ] **Content-hash pinning, verified source cache and offline replay**. Run again (2026-10-02) already detects a changed file by content; retained source copies are ratified but unimplemented ([Run again synthesis](/crosswalker/agent-context/zz-log/2026-10-02-recipe-run-again-synthesis/))
- [ ] **`mechanism: tag` and `mechanism: wikilink` layout levels, and `graph_edges`**: schema-reserved at v0.1
- [ ] **[Transform system](/crosswalker/design/transformation/) breadth** ([research](/crosswalker/agent-context/zz-log/2026-04-03-transform-engine-research/))

### Recipe authoring with AI assistance

A [recipe](/crosswalker/concepts/terminology/) is plain JSON, and since 2026-10-02 the recipe library imports and exports recipe files. What is missing is a native round trip with an assistant, preserving the full canonical `RecipeDocument` ([recipe fidelity synthesis](/crosswalker/agent-context/zz-log/2026-07-21-portable-import-recipe-fidelity-synthesis/)) and sending nothing without an explicit preview and opt-in.

- [ ] **Paste-JSON entry** beside the existing file import
- [ ] **Context-pack command**: copy [`spec/recipe.schema.json`](/crosswalker/agent-context/v0-1-schema-spec/), the recipe and the source's column headers in one action
- [ ] **Validate-on-paste**: name the offending field and the action at paste time

## Performance: v1.0+ companion plugins

Researched 2026-05-02 and reframed by the [v0.1 stack pivot](/crosswalker/agent-context/zz-log/2026-05-02-v0-1-initial-stack-pivot/) as opt-in companion plugins for users who outgrow the Tier 2 default.

- [ ] **Incremental Tier 2 projection**: the index persists since 2026-10-03, but every launch still runs a full startup refresh; skip unchanged notes
- [ ] **"Crosswalker Power Query"**: DuckDB-WASM + Oxigraph + Nemo, for vaults past the ~100K mapping ceiling ([Ch 18 triggers](/crosswalker/agent-context/zz-research/2026-05-02-challenge-18-tier-2-lite-rule-subset/#3-migration-trigger-spec), [Ch 14](/crosswalker/agent-context/zz-research/2026-05-02-challenge-14-missed-engines/))
- [ ] **Comunica federation** (conditional on an honest assessment; [third-wave §7.2](/crosswalker/agent-context/zz-log/2026-05-02-direction-third-wave-architectural-shifts/#72-confirmed-defaults--user-sign-off-received-2026-05-02))
- [ ] **Compliance-export mode**: T2/T3 audit profiles ([Ch 15 §E](/crosswalker/agent-context/zz-research/2026-05-02-challenge-15-non-git-audit-trail/)); needs v0.1.8 first
- [ ] **Migration trigger UX** and a "this will be heavy" confirm gate for large views
- [ ] **PQC dual-sign** (Ed25519 → ML-DSA-44) from 2027

## Deployment: v2.0+ Tier 3 server guide

A deployment guide, not plugin code ([Ch 16](/crosswalker/agent-context/zz-research/2026-05-02-challenge-16-tier-3-reconsideration/)): Postgres + JSONB + recursive CTE by default; Fuseki or oxigraph-server for SPARQL; layered Fuseki + DuckDB; TerminusDB as an opt-in mirror; Apache AGE as a Postgres fallback. Because files are canonical, moving engines means re-running the projector.
