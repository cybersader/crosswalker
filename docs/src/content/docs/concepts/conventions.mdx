Crosswalker is a **stack of layered conventions** — formalized systems (little languages, schemas, and vocabularies), some we built, some we adopted from existing standards and combined into a coherent whole. This page is the **map**: the entire pipeline at a glance, with each layer linking down to the page that goes deep. Start here; follow any layer that interests you.

<Aside type="tip" title="How to read this page">
This is a high-level **map of content** — a hub, not a deep-dive. **Don't recognize a term?** Every chip in the diagram is a link — click it to jump straight to its definition. For the *component + data-flow* detail see [system architecture](/crosswalker/concepts/system-architecture/). For the *front half* — how external data becomes a vault — see [Mapping into Obsidian](/crosswalker/concepts/mapping-into-obsidian/). For the *output language* see [data morphology](/crosswalker/agent-context/zz-log/2026-06-04-data-morphology/).
</Aside>

<Aside type="note" title="Artifact-role guardrails">
Use the distinctions in [artifact roles and authority](/crosswalker/concepts/artifact-roles-and-authority/): transforms are bounded changes; projections name their target; translation means a narrow interlingua/adapter step; compilation requires an explicit lowering architecture; recipes are machine-evaluable declarative specifications, not executable knowledge. SSSOM, STRM, OSCAL, CSV, and Markdown are serializations. ZIP files, folders, and git repositories are carriers, and only become packages when manifest semantics define the package.
</Aside>

## The stack at a glance

Every layer, the convention(s) it runs on, and whether we **built** it or **adopted / combined** an existing standard. **The chips are links** — click any term you don't recognize to jump to its definition. Data flows top to bottom; the **Tier 1 contract** (accent border) is the load-bearing middle. Crosswalker is **general-ontology**: GRC/compliance is the primary use case (the vast majority of usage), not the only one — so domain-specific pieces are marked (dashed) as use-case examples, not core architecture.

The shape is the design: **we built the morph (parse → recipe → render → contract) and the way you read it back (data morphology + lenses); we adopted proven standards wherever one existed** (CURIE for identity, STRM + SSSOM for crosswalk semantics, OSCAL for export, Bases + SQLite for query). Composing standards instead of reinventing them is what keeps a Tier 1 vault interoperable.

The pattern across the stack is not that every artifact is a DSL. Each role has an explicit contract: recipes are machine-evaluable declarative specifications, schemas validate canonical records, serializations represent exchanges, and renderers or projectors execute bounded operations. Those contracts keep the recipe schema decoupled from the engine, the engine from the Tier 1 schema, and the cache substrate from the schema. That decoupling *is* [the modularity goal](/crosswalker/agent-context/zz-log/2026-05-04-target-structure-synthesis/) made concrete.
