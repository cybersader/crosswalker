You need Crosswalker [installed and enabled](/crosswalker/getting-started/installation/) and a framework file to import: a CSV, XLSX, or JSON export of controls, requirements, or techniques. If you do not have the file yet, use the [framework data sources guide](/crosswalker/reference/framework-data-sources/) to find the publisher download, matching bundled recipe, licence caution, and exact import binding.

**Not yet verified in real Obsidian (2026-09-21):** the vault scan and the worksheet suggestion described below shipped on an unmerged branch without a screenshot run.

## Import your first framework

1. **Open the Crosswalker workspace tab.** Click the network-shaped ribbon icon, click the status bar count, or run **Crosswalker: Start here: open workspace** from the command palette (`Ctrl/Cmd + P`). You can also right-click a CSV, XLSX, or JSON file in the file explorer and choose **Import into vault with Crosswalker**, which skips straight to configuring it.

2. **Pick your file.** Above the picker, **Browse built-in import presets** lists every framework Crosswalker recognizes on sight, with a link to where you download each publisher's file and a link to the matching import instructions. If the file is already in the vault, **Find sources in this vault** on the workspace tab lists every framework export it recognizes and opens the one you pick where you decide what becomes real. For example, a NIST 800-53 controls export. Large CSVs stream in, so multi-megabyte files are fine. For XLSX you also pick the worksheet and header row; for JSON you pick which list of records to import. Before trusting a recognized-source import, check its [verified sheet, header row, count, and silent-failure gotchas](/crosswalker/reference/framework-data-sources/#silent-failure-checklist).

3. **Take the fast path if it's offered.** When your file's columns match a framework Crosswalker already knows (NIST CSF 2.0, NIST 800-53, MITRE ATT&CK, CIS Controls v8, the Secure Controls Framework, CRI Profile, and crosswalk files), a **Recognized source** card appears with a summary of what it found. For a recognized workbook, Crosswalker suggests the worksheet and header row, but keeps both controls editable and never advances for you. Choose **Import with this configuration** to accept it, or **Customize** to adjust it first.

4. **Otherwise, map your columns.** Tell Crosswalker what each column is for: which ones become folders, which become note titles, which become note properties, which become links to other notes, and which become body text. A live preview on the right shows a real folder tree and one fully rendered note, updating as you change things.

5. **Review and confirm.** The review screen shows the destination folder, a recap of every mapping, how many notes, folders, and links you'll get, and a plain-language warning if some rows don't fit the pattern you built.

6. **Generate.** Crosswalker writes the folders and notes into your vault.

Full detail on every screen is on the [import wizard](/crosswalker/features/import-wizard/) page.

## What you get

One note per row under your output folder (`Ontologies` by default). The bundled NIST 800-53 setup uses a flat layout, so the notes sit directly in that folder:

```
Ontologies/
├── AC-1.md
├── AC-2.md
├── AC-2(1).md
└── AU-1.md
```

Other import setups can use nested folders, headings, tags, links, or a combination. Crosswalker recognizes an imported framework from the identity recorded inside each generated note, not from the folder shape.

Each note carries your mapped columns as Obsidian properties, links to related notes, and a small record of where it came from:

```yaml
---
curie: "nist-mini:AC-2(1)"
title: Automated System Account Management
aliases:
  - AC-2(1)
tags:
  - framework/nist-mini/ac
family: AC
family_name: Access Control
control_id: AC-2(1)
parent: "[[AC-2]]"
_crosswalker:
  spec_version: "https://crosswalker.dev/spec/tier1.schema.json"
  source_ref:
    file: nist-mini.csv
    source_hash: sha256-380a762cd51be31c9f5d71ef8725a7863d3d07055a54e22dc5be3776088eac8a
  produced_at: "2026-05-04T00:00:00.000Z"
  producer:
    kind: plugin-engine
    name: crosswalker-plugin
    version: 0.1.0
---

# Automated System Account Management

## Description

Support the management of system accounts using automated mechanisms.
```

The `_crosswalker` block is how a re-import recognizes its own notes, so it updates them rather than creating duplicates. See the [generation engine](/crosswalker/features/generation-engine/) for exactly what lands in each note.

:::note[What a re-import preserves, and what it does not]
**You can write in a generated note.** Crosswalker owns a marked-off region of the
body and rebuilds only that. Everything you type outside it survives a re-import
exactly as you left it.

The region is delimited by two comment lines, invisible when you read the note and
visible while you edit it:

```markdown
<!-- crosswalker:body:start v=1 -->
# Automated System Account Management
...imported content, rebuilt on every import...
<!-- crosswalker:body:end -->

Our implementation: SSO provisioning via Okta.
Evidence: ticket SEC-4192.
```

Write **below the end marker** (or above the start marker). Text you put *inside*
the region is Crosswalker's to rebuild, and will be replaced.

What each existing-file mode does:

| Mode | Effect on a note that already exists |
|---|---|
| **Skip existing** (the default) | The note is left completely untouched. Nothing you wrote is at risk |
| **Replace** | Frontmatter keys you added are merged back, and only the marked region of the body is rebuilt. Every byte outside it is preserved |
| **Error** | The import stops rather than touching the existing note |

**Notes from before this feature**, which have no markers yet, are adopted the
first time you re-import them: if the body still matches what the import would
generate, Crosswalker adds the two marker lines and changes nothing else. If the
body has been edited, Crosswalker **leaves the file completely alone** and lists
it on the results screen as a note it could not safely update. It never guesses.

The same rule covers a note whose markers have been damaged, or one written by a
newer version of Crosswalker: the file is not modified at all, and the import
continues with the rest.

:::

## Where the settings are

Everything configurable lives in **Settings > Crosswalker**: the output folder, how property names are cased, how multi-value cells become lists, link style, how eagerly saved configurations are suggested, and the toggle for the live mapping workbench under **Import behavior**. See the [settings reference](/crosswalker/reference/settings/).
